**Status: generated Swagger 2 JSON and local HTTP behavior tested; live tenant import, authentication, invocation and Teams installation UNTESTED.** Do not treat the companion onepager as a completed deployment.

## Prepare

Complete [the group worksheet](../../docs/implementation-worksheet.md): named maker, tenant/environment, Copilot Studio license/capacity, security/DLP owner and data policy. The primary Microsoft route is [REST API tools (preview)](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agent-extend-action-rest-api). Microsoft calls for JSON OpenAPI v2; Microsoft states preview features are not meant for production use; keep this route to approved evaluation, not a production rollout.

`openapi-v2.json` is Swagger **2.0**, with POST `/ingest`, `/validate`, `/render`; operation IDs `rock_ingest`, `rock_validate`, `rock_render`; strict canonical evidence/draft request bodies and actual response shapes. Generated by `scripts/build_contracts.py` alongside OpenAI functions and canonical schemas.

## Resolve the deployment gap FIRST

The checked-in `host: 127.0.0.1:8765`, `schemes: [http]` accurately describes the **local-only dev server**, not a reachable Copilot service. Cloud Copilot cannot invoke it. Do not upload this local configuration expecting an operational connection. No public endpoint is provisioned by this kit.

A separate implementation must provide approved hosted HTTPS, tenant/user identity validation, meeting-scoped authorization, size/rate limits, audit logging without secrets/content, secret management, retention/deletion and operational controls. Do not tunnel/port-forward the dev server. Create a deployment-specific copy of the spec with the actual hosted host, HTTPS scheme and security definition **matching the implemented service**. Changing Swagger does not implement Entra/OAuth on the server.

## Import and wire (tenant operator, after hosting approval)

1. Create/select the approved Copilot Studio agent/environment/solution. Put the behavior from `prompts/master.md` in its instructions, preserve the human-review prohibition and do not expose unrelated connectors.
2. Tools → Add a tool → New tool → REST API. Upload the reviewed **deployment-specific Swagger 2 JSON**; inspect schema/tool names in the wizard.
3. Select auth matching the service. The local contract is `apiKey` in the `Authorization` **header**, whose full value must be `Bearer <ROCKNOTE_TOKEN>`; it is not `X-API-Key` and the token alone is invalid. Supply secrets through the platform's secure connection mechanism, never the prompt or repository. Do not select None. An OAuth hosted variant needs a corresponding implemented validator and updated spec, not reuse of the local bearer claim.
4. Select only ingest/validate/render. Confirm mappings send `{evidence}` or `{evidence,draft}`, not filenames or shell commands. Inspect responses before allowing automatic tool selection. Human review flags must remain false in model drafts.
5. Test synthetic fixtures: ingest; draft from approved model; validate; render restricted preview. Inject an unknown ref/fabricated quote and verify rejection. Verify missing credentials, wrong tenant/user and meeting-scope denial for the actual hosted design. Store sanitized screenshots/result IDs in the worksheet evidence location, not transcripts/secrets in Git.
6. Stop on import/schema/auth errors; capture the actual error, compare the installed product documentation, and revise generator/service together. A successful import is not invocation proof. A returned HTML string is not automatically a rendered Teams card.
